# 앱을 꺼 두면 복습 알림이 오지 않음 (등록 계정 오류)

## 증상
- 앱을 꺼 둔 상태에서 복습 시간이 돼도 알림이 오지 않았다. (A) 몰라요 10분 알림, (B) 아침 8시 알림 모두 오지 않았다.
- 2026-10-29에는 실제 폰으로 알림이 오는 것을 확인했었다.

## 원인
- 서버는 정상이었다. `cron.job`은 active였고, `net._http_response`에는 1분마다 200 `{"ok":true,"users":1,"sent":0}`이 쌓였다.
- `notif_log`의 마지막 기록은 2026-10-28 23:00 UTC(10-29 08:00 KST)였고, 그 뒤로는 0건이었다.
- `push_subscriptions`에 등록된 계정은 **테스트 계정 1개**뿐이었다. 이 계정은 마지막 접속이 10-28, 카드는 0장이었다. 실제 회원은 아무도 등록돼 있지 않았다.
- 코드 원인: '복습 알림 받기' 버튼(`togglePush`)이 "이 기기에 구독이 있으면 끄기"로만 동작했다. 그 구독이 지금 로그인한 계정 것인지는 확인하지 않았다. 로그아웃해도 구독은 예전 계정에 그대로 남았다.
- 찾은 방법: 서버 상태를 크론 → 호출 응답 → 발송 기록 → 등록 계정 순서로 SQL로 좁혀 갔다.

## 조치 (v44)
- `pushMine(cur)`로 이 기기의 구독이 지금 계정 것인지 확인한다. 다른 계정 것이면 해지한 뒤 새로 구독해 지금 계정으로 등록한다(`pushOn`).
- 로그인 후 알림이 꺼진 회원에게 「복습 알림 받을래요?」를 계정·기기마다 1회만 묻는다(`maybeAskPush`).
- 웹 알림은 기기마다 사용자가 허용해야 해서 서버에서 가입자 전원에게 보내는 방식은 불가능하다. 그래서 자동 질문으로 대신했다.
- 비용: 알림 전달은 무료(구글·애플 서버). `notify` 실행 횟수는 회원 수와 상관없이 월 약 4.3만 회(무료 한도 50만 회). 전송량은 아침 8시에 대상자 카드 정보만 내려받으므로 작다.

## 확인
- `node scripts/check_syntax.js` 통과.
- Playwright가 설치돼 있지 않아 헤드리스 확인은 하지 못했다. 알림은 실제 폰에서만 확인할 수 있다.
- 확인 대기: 폰에서 실제 계정으로 로그인 → 질문 또는 메뉴로 알림 켜기 → 아래 SQL에서 실제 계정 이름이 나오는지 확인 → 다음 날 아침 8시나 몰라요 10분 알림이 오는지 확인.
  ```sql
  select p.name from push_subscriptions s join profiles p on p.id = s.user_id;
  ```

## 배운 점
- "200 ok인데 sent 0"이면 서버 고장이 아니라 **보낼 대상과 조건**을 본다.
- 기기 단위 자원(푸시 구독)과 계정 단위 데이터가 섞이면, 계정을 바꿀 때 소유권 확인이 필요하다.
