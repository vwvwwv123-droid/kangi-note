# 홈 검색창을 누르면 자판이 안 뜨고 퀴즈 화면으로 넘어감

## 증상
- 홈(오늘) 화면의 한자 검색창을 누르면 **가끔** 자판이 안 뜨고 퀴즈 화면으로 넘어갔다.
- 사용자가 찾은 재현 순서: 카드 탭에 들어갔다 나온 뒤 검색창을 누르면 퀴즈로 넘어간다.
- 같은 원인으로 「오늘 카드 끝!」 화면의 「퀴즈로 확인하기」 버튼은 눌러도 반응이 없었다(코드로 추론, 헤드리스에서 확인).

## 원인
- 서로 다른 두 요소가 같은 id `sq`를 썼다.
  - 홈 검색창: `<input id="sq" type="search">` (`initSearch()`, 앱 시작 때 한 번 만듦)
  - 「오늘 카드 끝!」 화면 버튼: `<button id="sq">퀴즈로 확인하기</button>` (`renderStudy()`)
- 카드가 0장이 되면 `renderStudy()`가 `$('#sq').onclick=()=>go('quiz')`를 실행한다. `$`는 `document.querySelector`라서 **문서에서 먼저 나오는 요소 하나**를 잡는다. 홈(`#v-home`)이 카드 화면(`#v-study`)보다 앞에 있으므로 버튼이 아니라 검색창에 「누르면 퀴즈로」가 붙었다.
- 「간헐적」이었던 이유: 「오늘 카드 끝!」 화면이 한 번이라도 나와야 생긴다. 그날 카드를 이미 다 푼 상태면 카드 탭에 들어가기만 해도 바로 이 화면이 나온다. 새로고침하면 검색창이 새로 만들어져 사라진다.
- 찾은 방법: `index.html`에서 `#sq`를 grep → 같은 id가 두 곳(1720줄 검색창, 2562줄 버튼)에서 나옴.

## 조치
- 버튼 id를 `doneQuiz`·`doneExtra`로 바꿨다(옆의 「새 한자 5개 더」 `sx`도 같이).
- 찾는 범위를 카드 화면 안으로 좁혔다: `$('#sq')` → `el.querySelector('#doneQuiz')` (`el`은 `#v-study`).
  - 고른 이유: id만 바꾸면 나중에 또 이름이 겹칠 때 같은 문제가 난다. 범위를 좁히면 다른 화면의 같은 이름에 영향을 받지 않는다.
- 파일 전체에서 정적 `id="..."` 중복을 다시 찾았다 → 다른 중복 없음.

```js
// 전: 문서 전체에서 첫 번째 #sq (= 홈 검색창)를 잡음
$('#sq').onclick=()=>go('quiz'); $('#sx').onclick=()=>startStudy('extra');
// 후: 카드 화면 안에서만 찾음
el.querySelector('#doneQuiz').onclick=()=>go('quiz'); el.querySelector('#doneExtra').onclick=()=>startStudy('extra');
```

## 배운 점
- `$('#이름')`처럼 문서 전체에서 찾는 코드는 **같은 id가 두 개면 조용히 엉뚱한 요소**를 잡는다. 오류 메시지도 안 난다.
- 10/29 달력 `today` 클래스 충돌([[2026-10-29_달력-오늘칸-숫자-치우침]])과 같은 종류다. 모든 화면이 한 파일에 있어서 이름이 전역으로 겹친다. 새 id·클래스를 넣기 전에 `grep 'id="이름"'`으로 먼저 찾는다.
- 화면을 그때그때 다시 그리는 곳(`renderStudy` 등)은 `$` 대신 `el.querySelector`로 그 화면 안에서만 찾는다.
- 처음 배포 때 Claude의 push가 권한 검사에서 막혔는데, 사용자가 확인한 앱은 아직 옛 버전이었다. "고쳤는데 안 된다"면 **실제로 배포됐는지**(`git status`의 ahead, 앱 주소의 코드)부터 확인한다.
