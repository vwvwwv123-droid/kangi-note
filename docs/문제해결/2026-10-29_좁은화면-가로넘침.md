# 휴대폰에서 화면이 옆으로 넘쳐 손으로 축소해야 함

## 증상
- 아이폰·삼성 휴대폰에서 앱을 열면 화면이 옆으로 넘쳐서, 손가락으로 축소해야 전체가 보였다.
- v28 배포 후 사용자 캡처: 「오늘」 화면은 정상이었지만 **로그인 화면**의 카드가 오른쪽으로 밀렸다. 왼쪽 여백은 넓고 오른쪽은 잘렸다.
- v29 배포 후 사용자 캡처: 카드는 화면 안에 들어왔지만 **입력칸과 로그인 버튼이 카드 오른쪽 밖으로** 튀어나왔다. 사용자는 전체적으로 너무 크다고도 했다.

## 원인
- 두 곳 모두 grid로 된 화면 틀이 원인이었다. 열 폭이 `auto`라서 안에 든 요소의 최소 폭(min-content)이 화면보다 크면 열도 같이 늘어난다.
- ① v28: 「오늘」 검색 입력칸(`#sq`)이 기본 폭 약 201px을 유지했다. 그래서 폭 386px 미만 화면에서는 페이지가 386px로 넓어졌다.
- ② v29: 로그인 카드의 강숙이 그림(SVG)에 폭 속성이 없다. 실제 폰 브라우저는 이 그림의 최소 폭을 약 300px로 잡는다. 그래서 카드가 화면보다 넓어지고, 왼쪽부터 배치되면서 오른쪽이 잘렸다.
- ③ v30: 로그인 카드를 넓히던 **진짜 원인은 입력칸**이었다. 폰 브라우저가 입력칸 최소 폭을 크게 잡는데, v29가 카드 폭을 고정하자 입력칸만 카드 밖으로 나왔다. ②의 SVG 추정은 일부만 맞았다.
- 찾은 방법:
  - ①: 헤드리스 브라우저(Playwright, 모바일 모드)로 폭과 탭별 `scrollWidth`를 쟀다.
  - ②: 헤드리스 Chromium은 그림 최소 폭을 0으로 잡아서 재현되지 않았다. 사용자 캡처에서 카드의 좌우 여백 비율을 잰 뒤, 그림 최소 폭 300px을 강제로 넣어 재현했다. 그 결과 폭 360에서 카드 오른쪽이 화면 밖으로 6px 나갔다.

## 조치
- v28: `.sbox input`에 `width:0`을 추가했다. 기존 `flex:1`로 남는 폭을 채운다.
- v29: 로그인 화면 틀(`#authScreen`)과 공통 세로 틀(`.stack`)에 `grid-template-columns:minmax(0,1fr)`을 추가했다. 열 폭이 화면 폭을 넘지 못하므로, 안에 든 요소가 무엇이든 틀이 넓어지지 않는다. 앞으로 생길 수 있는 같은 종류의 문제도 함께 막는다.
- v30:
  - 로그인 폼(`.auth-form`, `.af`) 열을 `minmax(0,1fr)`로 바꾸고, 입력칸에 `width:100%; min-width:0`을 줬다.
  - 휴대폰(폭 520px 이하)에서만 여백·글씨를 약 15% 줄였다. 대상은 본문, 헤더, 탭, 카드 안쪽 여백, 큰 숫자, 로그인 그림 높이(최대 150px)다. 입력칸 글씨는 16px로 유지했다. 16px 미만이면 아이폰이 입력할 때 화면을 자동 확대한다.
  - 검색 결과가 없을 때 빈 결과 칸(`#sres:empty`)을 숨겨 빈 공간을 없앴다.
- `overflow-x:hidden`으로 넘침을 가리는 방법은 쓰지 않았다. 잘림은 그대로 남기 때문이다.

## 확인
- 헤드리스: 폭 320/360/375/390/412/430 × 로그인 + 6개 탭에서 넘침 0, 좌우 여백 같음(16px, 로그인 카드 32px).
- v30: 입력칸에 `size=45`를 넣어 최소 폭을 키운 상태(폰 흉내)로 폭 320~800 × 로그인·가입·6개 탭을 측정했다. 넘침 0, 카드 밖으로 나간 요소 0이다. 검색은 정상 동작한다.
- 폰과 같은 그림 처리 방식은 헤드리스로 완전히 흉내 내지 못했다.
- 2026-10-29 v30 배포 후 사용자가 **삼성 휴대폰**에서 로그인 화면과 오늘 화면이 정상인 것을 확인했다.
- **아직 확인하지 못한 것**: 아이폰. 주변에 사용자가 없어 나중에 확인하기로 했다.

## 배운 점
- 화면이 옆으로 넘치면 화면 폭별로 `scrollWidth`부터 잰다.
- **헤드리스 Chromium에서 정상이어도 실제 폰에서는 다를 수 있다.** 특히 크기 속성 없는 SVG, 이미지, 입력칸은 브라우저마다 최소 폭이 다르다. 실기기 캡처를 먼저 받는다.
- 한 열짜리 grid는 처음부터 `minmax(0,1fr)`로 열 폭을 고정한다.
- 사용자에게 "증상이 있는 화면"을 먼저 물었어야 했다. v28은 실제로 있던 문제를 고쳤지만, 사용자가 본 화면(로그인)은 아니었다.
