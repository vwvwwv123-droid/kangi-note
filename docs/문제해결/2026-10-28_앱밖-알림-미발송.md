# 앱 밖 알림(Web Push)이 한 번도 오지 않음

## 증상
- 2026-10-15에 복습 알림을 설정한 뒤 휴대폰에 알림이 한 번도 오지 않았다.
- 앱 안의 배지는 정상이라서, 알림을 보내는 서버 쪽 문제로 범위를 좁혔다.

## 원인
- ① Edge Function `notify`가 호출될 때마다 500 오류를 냈다. Secret에 저장된 VAPID 비공개키가 web-push가 요구하는 URL-safe Base64 형식이 아니었다(`+`, `/`, `=` 포함).
- ② pg_cron이 보내는 헤더 `x-cron-key` 값이 Edge Secret `CRON_KEY`와 달라서, 크론 호출이 막혔다(403).
- 찾은 방법: `net._http_response` 테이블에서 1분마다 쌓이는 크론 호출의 `status_code`와 `content`를 확인했다. `notif_log`에는 발송 기록이 0건이었다.

## 조치
- `notify` 함수에서 키를 읽을 때 URL-safe Base64로 바꾸도록 했다(앞뒤 공백·따옴표 제거, `+`→`-`, `/`→`_`, `=` 제거). 키를 다시 저장하는 것보다 같은 실수가 반복돼도 동작하는 쪽을 골랐다.
- 실패하면 단계(`vapid`/`run`)와 오류 이유를 응답에 담도록 바꿨다. 기존에는 500만 보여서 원인을 알 수 없었다.
- `CRON_KEY`를 새로 발급해 Edge Secret과 크론 헤더를 동시에 바꿨다.
- 알림 대상자의 progress만 조회하도록 바꿔 데이터 사용량을 줄였다.
- 재배포 후 Supabase 점검에 쓴 개인 액세스 토큰은 삭제했다.

## 확인
- 서버 기준으로 테스트 발송에 성공했고, 크론 응답이 200 `{"ok":true,...}`로 바뀌었다.
- 2026-10-29 실제 휴대폰에 알림이 도착하는 것을 사용자가 확인했다.

## 배운 점
- "아무 일도 안 일어남"이 증상이면, 먼저 호출 기록(`net._http_response`)부터 본다.
- 서버 함수는 실패 이유를 응답에 남겨야 다음에 빨리 찾을 수 있다.
